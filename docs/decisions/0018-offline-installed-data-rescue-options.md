# 0018 — حفظ نصب آفلاین موجود در صورت در دسترس نبودن کلید امضا

تاریخ: ۲۰۲۶-۱۰-۲۱. **PROPOSED — منتظر تصمیم مالک؛ هیچ انتقال یا تغییر هویت نصب اجرا نشده است.**

## مسئلهٔ واقعی

فایل اولیهٔ تحویلی `ir.lifeguide.app.device` با certificate ثبت‌شده در [baseline](../operations/personal-delivered-baseline.json) امضا شده است؛ ساخت بعدی certificate متفاوت دارد. موجودبودن کلید خصوصی اصلی هنوز **UNVERIFIED** است. Android برای به‌روزرسانی معمولی تطبیق certificate را بررسی می‌کند؛ داشتن APK، رمز پیش‌فرض debug یا ساخت یک کلید جدید، کلید خصوصی قبلی را بازیابی نمی‌کند. قفل تحویل PR40 باید بسته بماند.

در [مستند رسمی امضای Android](https://developer.android.com/studio/publish/app-signing#considerations)، certificate متفاوت به نصب app تازه با package متفاوت نیاز دارد. صفحه واقعاً در این بررسی با HTTP200 خوانده شد؛ این منبع، وجود کلید مالک یا امکان انتقال روی گوشی او را اثبات نمی‌کند. تنظیم ساخت آزمایشی قبلی امضای پایدار را نگه نداشته است؛ این ایراد فرایند تیم است و مالک مسئول ساخت اولیهٔ کلید نبوده است.

## گزینه‌ها و پیشنهاد مشروط

| گزینه | نتیجه | وضعیت |
| --- | --- | --- |
| A — کلید اصلی پیدا شود | package قبلی ثابت، versionCode بالاتر و آزمون دقیق فایل قدیمی → جدید در DB پیش‌فرض؛ سپس آپدیت معمولی بدون حذف برنامه. | اولویت اول؛ دسترسی به کلید هنوز UNVERIFIED. |
| B — نصب کناری و انتقال محلی رمزدار | app تازه کنار app قبلی با کلید پایدار مالک؛ انتقال یک‌باره فقط با رایانهٔ خود مالک؛ app قبلی و داده‌اش حفظ شوند. پس از اثبات انتقال، آپدیت‌های آینده روی هویت جدید ثابت می‌مانند. | پیشنهاد فقط اگر A ممکن نباشد؛ نیازمند تأیید طرح و سپس آزمون ساختگی. |
| C — ادامه با نصب فعلی | داده و نصب فعلی دست‌نخورده بمانند؛ اصلاحات جدید فعلاً روی آن قابل نصب اعلام نشوند. | وضعیت امن فعلی تا تصمیم بعدی؛ تکمیل نسخه گزارش نمی‌شود. |

تأیید B فقط اجازهٔ آماده‌سازی و آزمون ابزار با دادهٔ ساختگی است. انتقال واقعی فقط روی رایانه و گوشی مالک، با انتخاب صریح خود او و پس از قبولی پذیرش انجام شود؛ تیم به DB، فایل پشتیبان، کلید یا گذرواژهٔ واقعی دسترسی نمی‌گیرد. این سند مجوز merge، deploy، انتشار یا uninstall نیست.

برای پروفایل فرزند، توضیح قابل فهم و انتخاب صریح خود کاربر دربارهٔ داده‌های خروجی، مقصد فایل و دارندهٔ گذرواژه نیز لازم است. تأیید صاحب پروژه جای این انتخاب یا سیاست مجوز والد را نمی‌گیرد. ابزار backup نباید نمای والد یا امکان خواندن پنهان اطلاعات خصوصی ایجاد کند؛ ردکردن انتقال، نصب و دادهٔ فعلی را تغییر ندهد.

## طرح قابل بررسی برای B — هنوز پیاده‌سازی نشده

1. **هویت تازه:** پیشنهاد `ir.lifeguide.app.personal`، ثابت پس از نخستین تحویل تأییدشده؛ نام محصول LifeGuide باقی می‌ماند. هویت آنلاین `ir.lifeguide.app`، نصب قبلی `.device`، schema و JWT تغییر نمی‌کنند. این ID فعلاً فقط متن پیشنهاد است و در Gradle تنظیم نشده است.
2. **محل انتقال:** فقط رایانهٔ خود مالک؛ بدون اینترنت، cloud backup، سرویس خانوادگی یا AI. خروجی با رمزنگاری احرازاصالت‌شده و گذرواژهٔ محلی ساخته شود؛ هیچ داده یا گذرواژه در لاگ/چت/Git قرار نگیرد و فایل موقت بدون رمز باقی نماند. کلید امضای تازه جدا و امن، با مسیر بازیابی نگهداری شود.
3. **حفظ مبدأ:** هیچ uninstall/clear-data/reset/root اجرا نشود. امکان دسترسی محلی به همین نصب debug فقط پس از تأیید روی دادهٔ ساختگی بررسی شود؛ اکنون UNVERIFIED است. snapshot باید SQLite/WAL سازگار و هویت/رکوردها را کامل حفظ کند. اگر امکان دسترسی یا سازگاری اثبات نشد، عملیات متوقف شود و نسخهٔ اصلی باقی بماند.
4. **واردکردن امن:** فقط همان دادهٔ شخصی برنامه‌ریز؛ اعتبار schema، اندازه، رابطه‌ها، UUIDها و یکپارچگی بررسی شود. مقصد خالی و تراکنش اتمیک لازم است؛ import تکراری/ناقص نباید داده را دوبل، مخلوط یا پاک کند. فایل رمزدار پیش از اتکا با خواندن مستقل و بازیابی کامل آزموده شود.
5. **اعلان دو نصب:** نصب قبلی خودکار روشن/خاموش نشود؛ مالک وضعیت آن را صریح مدیریت کند تا دو اعلان نیاید. مجوز OS به app تازه منتقل نمی‌شود. اعلان در app تازه تا اجازهٔ صریح خاموش بماند؛ پس از آن آینده از SQLite دوباره زمان‌بندی شود، نه با بازپخش snapshot قدیمی alarm.
6. **تحویل صادقانه:** این مسیر «آپدیت همان نصب» نامیده نشود؛ انتقال یک‌باره به app کناری است. baseline امضای قبلی برای سبزکردن CI بازنویسی نشود؛ پذیرش app تازه و ارتقای نسخه‌های بعدی آن مستقل باشد. app قبلی تا تأیید کامل مالک قابل بازکردن بماند.

## پذیرش لازم پیش از هر انتقال واقعی — همه UNVERIFIED

- ساخت/نصب کناری با دادهٔ ساختگی، بدون تغییر مبدأ؛ تطبیق مستقل تمام UUIDها، نام/گروه/تم/همراه، برنامه‌ها، ساعت‌ها، استثناها، تیک و بایگانی پس از بازگشایی.
- رمز اشتباه، فایل خراب/ناقص، قطع اتصال یا کمبود فضا به خطای روشن برسند و هیچ مبدأ/مقصد سالمی را تغییر ندهند؛ تکرار import رکورد تکراری نسازد.
- مقصد و دامنهٔ داده پیش از خروجی روشن باشند؛ ردکردن رضایت کاربر هیچ فایل داده‌ای ایجاد نکند و نصب فعلی را دست‌نخورده بگذارد.
- بازگشایی هر دو نصب بعد از انتقال، آزمون اعلان با مبدأ خاموش/روشن با انتخاب کاربر و نبود اعلان تکراری؛ هیچ مجوز یا رضایت به‌طور ضمنی منتقل نشود.
- نصب نسخهٔ دوم app تازه با همان کلید ثابت و code بالاتر، روی DB پیش‌فرض واقعی و حفظ تمام داده‌های ساختگی، پیش از نامیدن آن به‌عنوان مسیر آپدیت آینده.

بدون تأیید B کد انتقال، هویت جدید، backup واقعی یا کلید تازه ایجاد نمی‌شود. سؤال باز فقط انتخاب این مسیر مشروط است؛ هیچ secret یا فایل خصوصی از مالک در چت خواسته نمی‌شود.
