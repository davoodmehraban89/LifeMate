# 0017 — اولویت نسخهٔ شخصی و حفظ داده هنگام به‌روزرسانی

تاریخ: ۲۰۲۶-۱۰-۲۱. **ACCEPTED برای ترتیب کار و معیار تحویل؛ گزینهٔ بازیابی کلید/انتقال داده هنوز PROPOSED است.**

مالک صریحاً خواست نسخهٔ آفلاین نصب‌شده ابتدا برای برنامهٔ هفته، تیک هر نوبت، شخصی‌سازی و یادآوری قابل اتکا تکمیل شود و سپس کار آنلاین ادامه پیدا کند. «آنلاین آماده است» ادعا نشده است. این تصمیم، رضایت تازه برای اشتراک داده با والد، AI، زیرساخت، پشتیبان ابری، merge یا deploy نیست. قرارداد ADR0016/D-A پابرجاست.

## معیار پذیرفته‌شدهٔ تحویل

1. بدون URL، حساب یا اینترنت؛ SQLite همین گوشی مرجع است. ثبت/ویرایش/تیک/بایگانی و نام/تم پس از بستن و بازکردن باقی بمانند.
2. به‌روزرسانی روی همان نصب: package و کلید امضای قبلی ثابت، versionCode افزایشی، بدون uninstall/clear-data/reset. خطای DB نباید با DB خالی پنهان شود.
3. پیش از تحویل، آزمون دقیق APK تحویلی قبلی → نامزد جدید با دادهٔ ساختگی در **DB پیش‌فرض محصول**، همراه SQL مستقل، حفظ UUIDها/استثناهای نوبت/انتخاب اعلان و نبود اعلان تکراری لازم است. fixture جداگانهٔ فعلی جای این آزمون نیست.
4. اعلان فقط با انتخاب کاربر؛ لحن حمایتی، نام همراه قابل انتخاب، متن عمومی بدون عنوان خصوصی کار و امکان خاموش‌کردن. مجوز/دقیق یا تقریبی/محدودیت اندروید روشن باشند. «زمان‌بندی» اثبات شنیده‌شدن صدا نیست.
5. آزمون گوشی برای اعلان با برنامه بسته، صدا، تغییر مجوز، reboot و Doze جدا ثبت شود. نتیجهٔ شبیه‌ساز جای گوشی نیست.

## مانع فعلی — VERIFIED از گواه فایل‌های ساخت، نه خواندن گوشی مالک

[کنترل تحویل](../operations/PERSONAL_UPDATE_GUARD.md) package/code/certificate فایل قبلی و PR39 را ثبت کرده است. certificateها متفاوت و هر دو code9 هستند. APK جدید با کلید تصادفی debug، ارتقای قابل قبول فایل قبلی نیست. موجودبودن کلید خصوصی قبلی **UNVERIFIED** است؛ داشتن APK یا certificate جای آن را نمی‌گیرد. کلید جدید نامرتبط، این نصب v2 را ارتقا نمی‌دهد. تحویل APK شخصی عمداً بسته شد؛ بازکردن قفل بدون پذیرش ارتقای DB مجاز نیست.

## گزینه‌ها برای تصمیم بعدی — هنوز انتخاب/اجرا نشده

| گزینه | کار لازم پیش از هر نصب | پیامد و محدودیت |
| --- | --- | --- |
| A — کلید اصلی موجود است | مالک/تیم فقط در محل امن، وجود کلیدی با fingerprint قبلی را بررسی کند؛ سپس secret manager و CI ایزوله، code افزایشی و پذیرش دقیق ارتقا آماده شود. کلید/رمز در چت یا Git قرار نمی‌گیرد. | مسیر مطلوب همان نصب؛ فعلاً وجود کلید تأیید نشده است. |
| B — کلید اصلی در دسترس نیست | ابتدا طرحِ نجات کاملاً محلی و رمزدار، مقصد فایل و بازیابی بررسی و تأیید شود؛ ابزار فقط با دادهٔ ساختگی آزموده شود. پیش از هر اقدام مخرب، بازیابی مستقل و کامل اثبات شود. | در صورت تأیید بعدی ممکن است به انتقال یک‌باره نیاز باشد؛ این سند مجوز uninstall یا خواندن دادهٔ واقعی کودک توسط تیم نیست. |
| C — حفظ نسخهٔ فعلی تا حل مانع | نصب فعلی و دادهٔ آن دست‌نخورده بمانند. | امن‌ترین حالت انتظار؛ اصلاحات جدید هنوز قابل نصب روی این نسخه اعلام نمی‌شوند. |

در وضعیت فعلی فقط حفظ نصب موجود اجرا می‌شود. هیچ دادهٔ واقعی کودک برای بررسی ارسال نشود. پشتیبان‌گیری خودکار Android/میزبان خارجی فعال نشده و export/restore هنوز وجود ندارد. حذف برنامه یا پاک‌کردن داده، فایل خصوصی SQLite را از بین می‌برد؛ قول بقای داده پس از uninstall داده نمی‌شود.

## ترتیب باقی‌مانده

۱) رفع مانع امضا/انتخاب مسیر حفظ داده؛ ۲) پذیرش دقیق ارتقا و سپس بازکردن کنترل تحویل با بازبینی؛ ۳) آزمون اعلان و مرور شمسی/RTL روی گوشی با دادهٔ ساختگی؛ ۴) تحویل محدود آفلاین با نسخه/هش/راهنما و ثبت بازخورد؛ ۵) پس از تکمیل این بسته، ادامهٔ نسخهٔ آنلاین در PRهای جدا. آموزش، AI، کنترل از راه دور والد و backup ابری به این بسته اضافه نمی‌شوند.
