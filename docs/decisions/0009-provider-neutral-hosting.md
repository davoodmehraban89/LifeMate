# ADR 0009 — میزبانی مستقل LifeGuide و آزمون Stage 0

تاریخ: 2026-10-08

وضعیت: پذیرفته‌شده برای بسته توسعه و آزمون محلی؛ انتخاب و راه‌اندازی میزبان عمومی **نیازمند تصمیم و مجوز مالک** است.

نام محصول: **LifeGuide / لایف‌گاید**؛ نام مخزن `davoodmehraban89/LifeMate` و شناسه‌های پروتکل تغییر نمی‌کنند.

## مسئله و تصمیم

کاربران داخل ایران باید API، PWA و APK را از یک مبدأ، بدون VPN و بدون وابستگی زمان اجرا به CDN یا دیتابیس مدیریت‌شده خارجی دریافت کنند. برنامه موجود Express، Argon2 بومی و PostgreSQL را حفظ می‌کنیم. Railway از گزینه‌های فعال کنار گذاشته شده؛ Firebase، Supabase، Neon، Cloudflare Workers/D1 و سایر PaaS/BaaS مدیریت‌شده در این تصمیم گزینه انتشار نیستند. سوابق آن‌ها فقط تاریخچه‌اند.

**گزینه اصلی فعلی Stage 0 است:** همان پشته آنلاین چندکاربره روی رایانه Windows مالک، Docker Compose و LAN خانگی، با HTTPS مورد اعتماد دستگاه‌های آزمون. این گزینه حساب میزبانی یا پرداخت نمی‌خواهد؛ برق، سخت‌افزار موجود و اتصال شبکه لازم‌اند. «آنلاین» در این مرحله یعنی چند دستگاه به **یک API و یک PostgreSQL واقعی** وصل می‌شوند؛ دسترسی اینترنت عمومی، آزمون داخل شبکه اپراتورها و انتشار محصول با آن اثبات نمی‌شود.

**مسیر جایگزین:** اجرای همین Compose روی یک سرور Linux موجود و در اختیار مالک داخل کشور، اگر مالک آن را انتخاب و مجاز کند. این توصیه خرید از ارائه‌دهنده ایرانی نیست. اگر چنین سروری وجود ندارد، Stage 0 ادامه می‌یابد؛ انتخاب خارجی تا رفع مانع پرداخت، احراز هویت و اثبات دسترسی داخل ایران باز می‌ماند.

## مقایسه گزینه‌ها

قیمت‌ها حاصل مشاهده صفحات رسمی در 2026-10-08 هستند، پیشنهاد خرید نیستند. **هیچ آزمون از داخل ایران اجرا نشده است.** ادعای فروشنده درباره ایران، دسترسی واقعی یا اعتبار IP را تأیید نمی‌کند.

بسته روی یک Linux VM معمولی قابل اجرا طراحی می‌شود؛ حداقل عملی حافظه/دیسک و بار Argon2 باید با آزمون همین بسته تعیین شود. ارزان‌ترین پلن 1 GB از صرف مشاهده قیمت، مناسب کل پشته فرض نمی‌شود.

**دام پرداخت:** Melbicom در UAE گزینه نزدیک دیگری است، اما طبق صفحه رسمی، اولین پرداخت برای KYC باید از روش دیگری انجام شود و رمزارز بعد از آن در دسترس است [S10]. BitPay ایران را در فهرست مناطق مسدود دارد [S11]. بنابراین عبارت «پذیرش رمزارز» مسیر پرداخت قابل استفاده برای مالک را اثبات نمی‌کند. Hetzner نیز رمزارز قبول نمی‌کند و روش‌های پرداختش لزوماً در همه کشورها ارائه نمی‌شوند [S12]. هیچ حسابی ساخته، ارائه‌دهنده‌ای تماس گرفته یا پرداختی انجام نشده است.

## قرارداد بسته استقرار

- فایل ریشه `docker-compose.yml` شامل API موجود، PostgreSQL و Nginx TLS است. فقط درگاه HTTPS لبه به LAN/میزبان منتشر می‌شود؛ PostgreSQL و API داخل شبکه Docker می‌مانند.
- همان مبدأ `/` برای PWA، `/api/` برای API، `/health` برای probe و `/downloads/LifeGuide.apk` برای APK انتخاب‌شده مالک استفاده می‌شود. APK عمومی منتشر نمی‌شود؛ فایل تحویل باید با کلید واقعی مالک امضا شده باشد.
- `config.json` حاوی تنظیمات عمومی زمان اجرا، بدون secret و بدون URL میزبانی کنارگذاشته‌شده است. CanvasKit و فونت‌ها باید همراه خروجی وب و از همان مبدأ سرو شوند.
- `.env.example` فقط نام متغیرها/placeholder است. `.env`، کلید TLS، کلید امضا و backup در Git قرار نمی‌گیرند. کلمات عبور دیتابیس و کلید JWT در محیط محلی تولید و نگهداری می‌شوند؛ issuer/audience فعلی حفظ می‌شوند.
- اسکریپت‌های `scripts/local-deploy.sh` و `scripts/local-deploy.ps1` مخصوص اجرای محلی‌اند. workflow استقرار به‌صورت پیش‌فرض خاموش است؛ وجود آن مجوز اجرای زنده نیست.
- پشتیبان PostgreSQL از اسکریپت‌های موجود `backend/scripts/backup.sh` و `restore.sh` استفاده می‌کند. restore مخرب روی پایگاه مقصد باید فقط در مقصد آزمایشی یا با مجوز صریح عملیات انجام شود.
- runbookها: [Stage 0](../operations/STAGE0.md)، [استقرار خودمیزبان](../operations/SELF_HOSTED_DEPLOYMENT.md)، [مهاجرت داخلی](../operations/DOMESTIC_MIGRATION.md). این ADR به‌تنهایی اثبات اجرای بسته، backup یا مهاجرت نیست؛ شواهد اجرا در گزارش تحویل ثبت می‌شود.

## کارهای دستی مالک برای Stage 0

1. Windows، WSL2 و Docker Desktop/Compose را طبق [مستند رسمی Docker][S1] آماده کنید. نیازی به ثبت حساب میزبان نیست. اگر دریافت اولیه وابستگی‌ها مسدود است، توسعه‌دهنده می‌تواند ایمیج‌ها و ابزارهای بررسی‌شده را آفلاین منتقل کند؛ کلاینت در زمان اجرا به registry وصل نمی‌شود.
2. PC و Android/iPhone را به یک LAN مورد اعتماد متصل کنید؛ guest network یا client isolation را برای همین شبکه آزمون بررسی کنید. با `ipconfig` آدرس IPv4 کارت شبکه PC را پیدا کنید و در router برای آن DHCP reservation بگذارید. مثال `192.168.1.10` صرفاً نمونه است.
3. mkcert را از [منبع رسمی][S2] نصب کنید و از ریشه مخزن در PowerShell اجرا کنید. مقدار مثال را با IP واقعی PC عوض کنید:

   ```powershell
   New-Item -ItemType Directory -Force deployment/tls | Out-Null
   mkcert -install
   mkcert -cert-file deployment/tls/server.pem -key-file deployment/tls/server-key.pem 192.168.1.10 localhost 127.0.0.1
   mkcert -CAROOT
   ```

   فقط `rootCA.pem` را از مسیر آخر روی دستگاه‌های شخصی آزمون منتقل کنید. `rootCA-key.pem` و `server-key.pem` را در چت، Git، APK یا دستگاه‌های دیگر قرار ندهید. CA محلی برای انتشار کاربران عمومی نیست.
4. iPhone/iPad: گواهی را روی دستگاه باز و profile را در Settings نصب کنید؛ سپس Settings → General → About → Certificate Trust Settings، full trust همان CA را فعال کنید [S3]. Safari باید URL HTTPS بدون هشدار گواهی باز کند. Android: CA را از تنظیمات امنیت دستگاه به‌عنوان CA certificate نصب کنید؛ فقط نسخه توسعه مجاز است این CA را برای اتصال اپ قبول کند. نصب CA به‌تنهایی برای transport مبتنی بر Dart اثبات اعتماد نیست؛ آزمون app/TLS واقعی باید انجام شود. در release، اعتماد عمومی سیستم حفظ می‌شود و دورزدن اعتبارسنجی TLS مجاز نیست [S13].
5. اسکریپت Stage 0 در اولین اجرا `.env` را از نمونه، با secretهای تصادفی محلی و origin انتخاب‌شده می‌سازد؛ `.env` قبلی را خودکار بازنویسی نمی‌کند. origin/API runtime را روی `https://<LAN-IP>` بگذارید. دستور مورد انتظار بسته از ریشه مخزن:

   ```powershell
   ./scripts/local-deploy.ps1 -Origin https://192.168.1.10 -Certificate deployment/tls/server.pem -PrivateKey deployment/tls/server-key.pem -Project lifeguide-stage0
   ```

   IP مثال باید عوض شود. جزئیات build، migration و ایجاد `config.json` در [STAGE0.md](../operations/STAGE0.md) است. این دستور روی Windows مالک **UNVERIFIED** است؛ گزارش اجرای Linux/Compose جای آن را نمی‌گیرد. `docker compose config` خروجی secretدار می‌تواند داشته باشد؛ آن را عمومی یا در چت ارسال نکنید.
6. اگر Windows Firewall مانع ارتباط است، فقط TCP 443 را روی Private profile و `LocalSubnet` برای LAN مورد اعتماد باز کنید. port-forward روی router، تونل عمومی، DNS عمومی یا دسترسی WAN در این مرحله انجام ندهید. دستور نمونه با PowerShell مدیر برای همین PC:

   ```powershell
   New-NetFirewallRule -DisplayName 'LifeGuide Stage 0 HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 443 -Profile Private -RemoteAddress LocalSubnet
   ```

7. Safari را به `https://<LAN-IP>/` ببرید، با حساب والد **آزمایشی** وارد شوید و Share → Add to Home Screen را اجرا کنید. Android را روی همین مبدأ تنظیم کنید. سناریوی چندکاربره باید API/DB مشترک را بررسی کند؛ ذخیره محلی یا صفحه بازشده بدون داده کافی نیست.
8. تست شبکه `scripts/reachability-smoke.mjs` را طبق runbook اجرا کنید. برای CA محلی می‌توان Node را با `NODE_EXTRA_CA_CERTS` حاوی مسیر **گواهی عمومی** rootCA اجرا کرد؛ از `NODE_TLS_REJECT_UNAUTHORIZED=0` یا گزینه skip TLS استفاده نکنید. نتیجه باید TLS، `/health`، PWA و round-trip داده آزمایشی را جدا نشان دهد. پاسخ 200 health به‌تنهایی CRUD/مجوز/همگام‌سازی را تأیید نمی‌کند.
9. پس از آزمون، وضعیت خواب PC، روشن بودن Docker، آخرین sync و backups را بررسی کنید. هنگام پایان استفاده از CA آزمایشی، profile/trust آن را از دستگاه‌ها حذف کنید؛ rule فایروال را می‌توان با `Remove-NetFirewallRule -DisplayName 'LifeGuide Stage 0 HTTPS'` حذف کرد.

## تصمیم بعدی میزبانی عمومی، فقط توسط مالک

1. ابتدا Stage 0 و آزمون‌های API/مجوز/backup/restore با داده ساختگی را تمام کنید. انتخاب یک VPS بدون این شواهد، نقص برنامه را حل نمی‌کند.
2. برای نامزد خارجی، مالک باید قبل از ثبت/پرداخت از مسیر مجاز خود، پذیرش اقامت ایران، KYC، روش پرداخت اولیه/تمدید، شرایط حذف داده، مالکیت IP و سیاست بازپرداخت را تأیید کند. تیم در این نوبت پیام یا درخواست به فروشنده نمی‌فرستد. هیچ ادعای vendor درباره رمزارز به‌عنوان مسیر عملی پرداخت مالک پذیرفته نشده است.
3. پس از انتخاب و مجوز مالک، فقط داده ساختگی روی میزبان خارجی قرار می‌گیرد. دسترسی دامنه/IP واقعی باید از چند اپراتور داخل ایران، بدون VPN، با زمان، TLS و نتیجه PWA/API/APK ثبت شود. تست از محیط توسعه خارجی و looking glass جای این پذیرش را نمی‌گیرد.
4. مالک دامنه/IP و گواهی را انتخاب و تغییر DNS یا انتشار را جداگانه مجاز می‌کند. endpointها به یک origin می‌روند؛ دیتابیس مدیریت‌شده یا CDN خارجی زمان اجرا اضافه نمی‌شود. IP reputation، دسترسی IPv4، چرخه تمدید TLS و دسترسی هنگام اختلال اینترنت باید بررسی شوند؛ اعلام fallback URL مجوز ارسال داده به میزبان دیگری نیست.
5. برای استفاده واقعی خانوادگی، private notes، چت AI، سلامت/چرخه و داده حساس روانی روی میزبان خارجی منتقل نمی‌شود. درگاه‌های حقوقی/رضایت برای کودکان و نگهداری داده سلامت در کشور باید جدا تعیین شوند؛ این ADR آن‌ها را پیاده‌سازی یا تأیید حقوقی نمی‌کند. AI/voice خارجی خاموش می‌ماند.
6. مهاجرت به سرور داخلی باید با [runbook مهاجرت](../operations/DOMESTIC_MIGRATION.md)، backup/restore آزمایشی، صحت نسخه/env، برنامه توقف نوشتن و rollback انجام شود. `pg_dump/restore` محلی با داده ساختگی می‌تواند اجرا و ثبت شود؛ انتقال داده واقعی، DNS cutover و خاموشی میزبان قبلی در این کار **انجام نشده و UNVERIFIED** هستند.

## شواهد و حدود اعتبار

تحقیق صفحات رسمی و مطالعه کد مخزن انجام شد؛ هیچ account، VM، DNS، deploy زنده، پرداخت یا migration داده واقعی انجام نشد. دسترسی داخل ایران، نصب روی Windows مالک، TLS Android واقعی، Safari Add to Home Screen و عملکرد میزبان خارجی **UNVERIFIED** تا اجرای پذیرش مربوط‌اند. ریز مشاهده‌ها در [یادداشت تحقیق](../audits/2026-10-08-hosting-research.md) ثبت است.
