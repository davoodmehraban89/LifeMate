# برنامه اصلاح محدود درخواست و نشست Backend

تاریخ: ۲۰۲۶-۱۰-۰۸. شاخه مستقل: `fix/backend-request-safety`؛ شروع از بسته ماندگاری محلی `4d74cf2`. مسئول اصلی پیاده‌سازی: backend_safety_fix؛ هماهنگی و بازبینی نهایی: عامل اصلی.

## دامنه و معیار پذیرش

ممیزی entrypoint واقعی نشان داد Phase 6 پیش از parser/CORS نصب شده، JSON معتبر در نوشتن خطای ۵۰۰ می‌دهد، JSON ناقص ممکن است بدنه حساس را در لاگ درج کند، و نشست حساب disabled همچنان پذیرفته می‌شود. این بسته فقط همین خرابی‌های اجرایی را اصلاح می‌کند؛ سیاست سرپرست، اشتراک منتخب، schema پروفایل و رضایت سلامت موضوع بسته جداست.

- parser محدود و CORS با allowlist قبلی پیش از همه routerها؛ GET و preflight Phase 6 نیز پوشش داده شوند. PUT/DELETE در روش‌های مجاز، بدون بازکردن origin جدید.
- JSON ناقص پاسخ ۴۰۰ و body بیش‌ازحد پاسخ ۴۱۳ بدهد؛ log خطا فقط metadata مجاز داشته باشد، بدون body/password/token یا جزئیات داده.
- PATCH پروفایل ایران و PUT آموزش با JSON معتبر واقعاً ذخیره و پس از GET بازیابی شوند؛ مسیر سلامت موجود فقط در fixture مصنوعی مالک آزمایش شود و مجوز تازه‌ای ایجاد نکند.
- حساب غیرفعال در auth مشترک، refresh و Phase 6 رد شود؛ تغییرات schema یا لغو حساس عضویت خانواده انجام نشود.
- آزمون با HTTP واقعی entrypoint و PostgreSQL مستقل باشد؛ RED، سپس GREEN، آزمون‌های موجود و syntax نیز ثبت شوند. تست بدون دیتابیس skip نباید به‌عنوان موفقیت این مسیر گزارش شود.

## اجرا

۱. نوشتن regression با fixture مصنوعی در دیتابیس مستقل `lifemate_backend_safety`؛ capture لاگ production بدون چاپ payload.

۲. اصلاح حداقلی middleware، handler خطا و بررسی حساب فعال؛ حفظ قرارداد import `server.js` برای آزمون‌های فعلی.

۳. اجرای تازه همه آزمون‌ها، بازبینی مستقل و commit کوچک؛ گزارش نتیجه و SHA در `docs/audits/2026-10-08-backend-request-safety.md`.

هیچ استقرار، migration روی داده زنده، تغییر مجوز سرویس، قطع Railway یا انتشار عمومی در این بسته مجاز یا انجام‌شده نیست.
