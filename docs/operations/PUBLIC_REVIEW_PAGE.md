# صفحه عمومی بررسی LifeGuide و اتصال دامنه

این خروجی، معرفی عمومی محصول برای مشاهده و بررسی درخواست کاوه‌نگار است. API/PostgreSQL، ورود OTP، نصب PWA اپلیکیشن و APK عملیاتی را به‌تنهایی فعال نمی‌کند. نام سایت LifeGuide/لایف‌گاید است؛ نام مخزن و پروتکل تغییر نمی‌کنند. تصاویر مالک نشان می‌دهند قالب `lifeguideotp` هنوز تأیید نشده و کارشناس لینک را قابل بررسی ندیده است؛ این مشکل با صدور ادعای تأیید یا شبیه‌سازی ورود حل نمی‌شود.

## محتوای قابل بازبینی و آزمون

منبع: `site/review/`. فایل‌های HTML/CSS/فونت/نشان همگی محلی‌اند. این سایت JavaScript، API، فرم دریافت شماره، iframe و analytics ندارد. صفحه‌های عمومی هیچ ارجاعی به گیت‌هاب، مخزن یا سورس محصول ندارند و همه پیوندها داخلی‌اند. راه ارتباطی پشتیبانی در انتظار فعال‌سازی است؛ ایمیل، شماره یا فرم ساختگی معرفی نمی‌شود.

```bash
python3 scripts/check-review-site.py
python3 -m http.server 8765 --bind 127.0.0.1 --directory site/review
```

این HTTP محلی فقط مشاهده developer است، پذیرش HTTPS عمومی یا Safari نیست. خروجی CI فقط `site/review` را بسته‌بندی می‌کند؛ keystore، env، APK، کد Backend و داده خصوصی وارد Pages نمی‌شوند. `build-info.json` فقط نام محصول، هدف صفحه و `liveLogin:false` را ثبت می‌کند؛ شناسه commit/run و مسیر مخزن در خروجی عمومی قرار نمی‌گیرند. شواهد منبع ساخت در اجرای Actions باقی می‌مانند.

## انتشار GitHub Pages

Settings → Pages باید Source=`GitHub Actions` و Custom domain=`app.lifeguide.ir` داشته باشد؛ read-only API فعلی هر دو را تأیید کرده است. Workflow `.github/workflows/publish-static.yml` جایگزین مسیر قدیمی انتشار Railway/APK می‌شود؛ tag/release/force-push یا credential ارائه‌دهنده نمی‌سازد. PR فقط validate/build/upload می‌کند؛ deploy فقط روی main و در محیط موجود github-pages انجام می‌شود. مجوز محیط فعلی فقط main است و تغییر نکرده است.

پس از آزمون و تأیید نهایی مالک برای ادغام PR همین صفحه، push main انتشار را آغاز می‌کند. در run واقعی باید build و deploy موفق شوند؛ فقط سبزشدن build به معنی انتشار نیست. در دامنه، title، متن LifeGuide، لینک‌های حریم خصوصی و build-info باید مستقل خوانده شوند. main قبلی همچنان workflow تاریخی خود را دارد؛ تا ادغام این PR، نباید با dispatch آن مسیر قدیمی را به‌عنوان صفحه جدید منتشر کرد.

## تنها تغییر لازم DNS در پنل آروان

Zone: `lifeguide.ir`.

| فیلد | مقدار |
|---|---|
| نوع | CNAME |
| نام/زیردامنه | app |
| مقصد | davoodmehraban89.github.io |
| Proxy/CDN/ابر | خاموش؛ DNS-only |
| TTL | 300 یا پیش‌فرض پنل |

اگر app از قبل CNAME است، مقصد را بررسی و فقط proxy آن را خاموش کنید. اگر A/AAAA دستی برای همان app وجود دارد، پس از ثبت مقادیر قبلی، رکورد متعارض همان نام باید با CNAME درست جایگزین شود؛ CNAME با A/AAAA هم‌نام هم‌زمان معتبر نیست. دامنه اصلی، NSها، MX/ایمیل و TXT تأیید دست نمی‌خورند. مقدار مقصد https یا مسیر `/LifeMate` ندارد.

این پیشنهاد پس از بررسی فعلی است و تغییر DNS توسط تیم اجرا نشده است؛ ابزار متصل برای پنل آروان در دسترس نیست. پاسخ عمومی فعلی IPهای آروان `185.143.233.132` و `185.143.234.132` است؛ این پاسخ نمی‌گوید رکورد داخل پنل الزاماً از نوع A است، چون proxy می‌تواند CNAME را پنهان کند.

بعد از پایان TTL، CNAME عمومی و وضعیت DNS Pages دوباره بررسی شود. وقتی گواهی GitHub آماده شد، Enforce HTTPS فعال شود. هیچ TLS bypass یا گواهی self-signed برای کارشناس عمومی استفاده نشود. در صورت نیاز، بازگشت DNS با مقادیر ثبت‌شده قبلی انجام می‌شود؛ سرویس‌های دیگر حذف نمی‌شوند.

## بررسی و پاسخ کاوه‌نگار

مالک لینک دقیق `https://app.lifeguide.ir/` را با copy/paste ثبت کند؛ شکل جابه‌جای `https:/` یا slash در نمایش RTL به‌تنهایی اثبات غلط‌بودن مقدار پنل نیست. بعد از انتشار موفق و مشاهده از شبکه ایران بدون VPN، متن پیشنهادی پاسخ تیکت:

> سلام. صفحه معرفی لایف‌گاید در https://app.lifeguide.ir/ قابل مشاهده است و توضیح کاربرد برنامه، حریم خصوصی و استفاده از پیامک فقط برای ورود/تأیید هویت در آن درج شده است. لطفاً الگوی lifeguideotp را مجدداً بررسی بفرمایید. سپاس.

این متن تا پیش از آن بررسی نباید با ادعای «قابل مشاهده است» ارسال شود. تیم در این بسته تیکت، ایمیل یا پیامک ارسال نمی‌کند. تأیید نهایی با کاوه‌نگار است؛ مشاهده صفحه تضمین تأیید الگو نیست. کلید API و سایر secretها در GitHub Secrets یا محیط Backend قرار می‌گیرند و هرگز در HTML/JavaScript، مخزن یا چت نوشته نمی‌شوند. اتصال provider، صحت OTP/انقضا/محدودیت تلاش و رسیدن پیامک به گوشی بعد از تأیید، جدا آزموده می‌شوند.
