# بررسی و آماده‌سازی محتوای LifeGuide

این بسته ابزار محلی بازبینی را به دروازه‌های موجود دیتابیس در مهاجرت‌های
0013 و0015 متصل می‌کند. ابزار، مشاهدهٔ فیلم یا تأیید مدرس متخصص را انجام
نمی‌دهد. منابع واقعی و پیش‌نویس ریاضی اول همچنان DRAFT هستند؛
`reviewRecord:null` نباید با تأیید ساختگی جایگزین شود.

**در این نسخه، نوشتن فقط روی محتوای آزمایشی ساختگی مجاز است.** هیچ فرمان
این راهنما برای سرور زنده، انتشار عمومی، دادهٔ واقعی خانواده یا تغییر
مجوزهای زنده تأیید نشده است. ابزار هیچ فیلمی دانلود نمی‌کند و به سرویس
هوش مصنوعی، پیامک، ایمیل یا آپارات درخواست شبکه نمی‌فرستد.

## پیش‌نیاز و اتصال

Node22، PostgreSQL و مهاجرت0020 لازم‌اند. اتصال را از فایل خصوصی خارج
مخزن یا secret manager بارگذاری کنید. رمز و URL حاوی رمز را در تاریخچهٔ
ترمینال، چت، فایل JSON عملیات یا مخزن قرار ندهید.

متغیرهای لازم:

- `CONTENT_REVIEW_DATABASE_URL`: اتصال جداگانهٔ اپراتور/مهاجر به دیتابیس
  آزمایشی روی `localhost`، `127.0.0.1` یا `::1`.
- `CONTENT_REVIEW_SYNTHETIC_ONLY=true`: فعال‌سازی صریح عملیات آزمایشی.

ابزار از `DATABASE_URL` برنامه به‌عنوان جایگزین استفاده نمی‌کند. پارامتر
query و fragment اتصال پذیرفته نمی‌شوند؛ این پارامترها می‌توانند تنظیمات
درایور را تغییر دهند. نام دیتابیس باید `lifeguide_*test` با پسوند مجاز،
`lifemate_ci` یا نام دقیق آزمون تفکیک نقش‌های پروژه باشد. کاربر
`lifeguide_api` و `lifeguide_backup` مجاز به اجرای ابزار نیستند. اپراتور
نوشتن باید UPDATE منابع و INSERT/UPDATE تعریف آزمون و INSERT دفتر عملیات
را داشته باشد؛ نقش API فقط خواندن تعریف‌های آموزشی را دارد.

## مشاهده و بررسی بدون تغییر

از پوشهٔ `backend`، پس از بارگذاری خصوصی متغیرها:

```bash
node scripts/review-learning-content.js inspect video VIDEO_UUID
node scripts/review-learning-content.js inspect assessment ASSESSMENT_UUID
node scripts/review-learning-content.js dry-run /private/path/operation.json
```

شناسه‌ها را با UUID موجود در دیتابیس آزمایشی جایگزین کنید. `inspect` وضعیت
فعلی، هش ثبت‌شده، هش محاسبه‌شده، هش زمینه و صلاحیت فعلی نمایش را در یک
snapshot فقط‌خواندنی برمی‌گرداند. هش ویدیو اثرانگشت **فرادادهٔ ثبت‌شده**
است؛ ثابت‌ماندن فایل ویدیو در میزبان، مشاهدهٔ کامل یا حق نمایش را اثبات
نمی‌کند.

`dry-run` همان اعتبارسنجی وضعیت، نسخه، هش، چاپ کتاب و گواهی بازبینی را در
تراکنش فقط‌خواندنی اجرا می‌کند. خروجی `mode:dry-run` هیچ تغییر یا رسید
پایدار ایجاد نمی‌کند. وضعیت `proposedStatus` صرفاً نتیجهٔ بررسی پیشنهادی
است. ورودی فایل باید JSON معمولی و حداکثر1MiB باشد؛ فیلدهای ناشناخته و
فیلدهای اطلاعات خصوصی رد می‌شوند.

## قرارداد فایل عملیات

هر عملیات شامل `schemaVersion:1`، یک `mutationId` ثابت، `entityType`
(`video` یا `assessment`)، `entityId`، `operation` و مقادیر مشاهده‌شدهٔ
`expectedStatus`، `expectedContentHash` و `expectedContextHash` است.
عملیات آزمون علاوه بر این‌ها `expectedVersion` دارد. UUID عملیات را پس
از پاسخ نامشخص تغییر ندهید؛ تکرار همان فایل، رسید قبلی و وضعیت **فعلی**
محتوا را برمی‌گرداند. تغییر فایل با همان UUID با `mutation_id_reused` رد
می‌شود. نسخه/هش/وضعیت قدیمی نیز بدون تغییر داده رد می‌شود.

برای ساخت یا اصلاح آزمون، `operation:draft_assessment` و `unitId` و
`questions` لازم‌اند. تعریف جدید `expectedStatus:absent`،
`expectedVersion:0` و `expectedContentHash:null` دارد. هش زمینهٔ تعریف
جدید را اپراتور از فرادادهٔ فعلی درس با تابع صادرشدهٔ
`assessmentContextHash` در `src/learning_assessment.js` محاسبه می‌کند:
`book_code`، `school_year`، `book_evidence_url`، `unit_key`،
`unit_title_fa` و `unit_evidence_url`. `inspect assessment` فقط برای تعریف
موجود کار می‌کند؛ رابط ساخت فایل اولیه از درس در این بسته پیاده نشده
است. `dry-run` هر اختلاف با زمینهٔ واقعی دیتابیس را رد می‌کند.

هر سؤال شامل `id`، `objectiveId`، `promptFa`، `choices`،
`correctChoiceId`، `explanationFa` و `remediationFa` است؛ هر گزینه فقط
`id` و `textFa` دارد. حداکثر20 سؤال و2 تا6 گزینه برای هر سؤال مجاز است.
ساخت پیش‌نویس، تأیید آموزشی محسوب نمی‌شود. تغییر پیش‌نویس یا تعریف
پس‌گرفته‌شده نسخه را یک واحد زیاد و بازبینی را خالی می‌کند. تعریف منتشرشده
قابل ویرایش نیست؛ ابتدا باید با عملیات مستقل پس گرفته شود. snapshot
سؤال‌های تلاش‌های قبلی دانش‌آموز حفظ می‌شود.

برای `operation:publish`، گواهی `review` باید با کتاب/سال/درس و هش جاری
منطبق و تاریخ آن معتبر و گذشته باشد. گواهی ویدیو شامل این تأییدهای صریح و
شرح مستند هرکدام است: مشاهدهٔ تمام فیلم، انطباق چاپ، صحت، تناسب سنی، حق
embed و پوشش پرسش‌ها. گواهی آزمون شامل صحت، تناسب، انطباق چاپ، پوشش هدف،
هش محتوا/زمینه و یادداشت بازبینی است. چاپ نامشخص، درس غیرفعال، دسترسی
غیررایگان فیلم، گواهی ناقص یا هش ناهماهنگ قابل انتشار نیست.

## اعمال آزمایشی و پس‌گرفتن

```bash
node scripts/review-learning-content.js apply /private/path/operation.json
```

علاوه بر اتصال محلی آزمایشی، کلید کتاب باید با
`synthetic-publication:` شروع شود. گواهی انتشار نیز باید
`evidenceScope:SYNTHETIC_TEST_ONLY` و نام بازبین با پیشوند `SYNTHETIC`
داشته باشد. این شرط مانع تبدیل منابع واقعی تحقیق به محتوای ظاهراً
تأییدشده می‌شود. پرچم true در یک fixture اثبات بازبینی انسانی نیست.

برای پس‌گرفتن، فایل تازه با UUID تازه، `operation:withdraw` و وضعیت/هش
جاری بسازید؛ `review` در این عملیات وجود ندارد. رسید انتشار قدیمی پس از
پس‌گرفتن، محتوا را دوباره منتشر نمی‌کند. همزمانی واردکننده/اپراتور با قفل
مشترک کاتالوگ و قفل ردیف‌ها کنترل می‌شود؛ اصلاح زمینه هنگام انتظار، گواهی
قدیمی را نامعتبر می‌کند.

جدول `content_publication_audit` فقط شناسه، هش، وضعیت، نسخه، نقش اپراتور
و زمان پذیرش را ذخیره می‌کند. متن بازخورد، نام خانواده، چت، یادداشت، سلامت،
پاسخ دانش‌آموز یا نثر گواهی بازبین به این دفتر منتقل نمی‌شود. مسیر HTTP
برای انتشار یا اعطای مجوز اضافه نشده است.

## شواهد این بسته و محدودیت‌ها

در2026-10-12، Node22.23.3 روی دیتابیس تازهٔ محلی PostgreSQL16 با
مهاجرت‌های پایدار0001–0015 و0020 اجرا شد: **12/12 آزمون موفق، صفر خطا،
لغو یا skip**. فرمان‌های واقعی CLI برای مشاهده، dry-run، اعمال، تکرار و
پس‌گرفتن اجرا شدند. دو درخواست همزمان یک رسید ایجاد کردند؛ انتظار واقعی
قفل با `pg_blocking_pids` مشاهده و اصلاح همزمان زمینه بدون انتشار رد شد.
دو نقش NOLOGIN با نام تصادفی و SELECT-only فقط در fixture مستقل آزموده
و پاک شدند؛ نقش‌های مشترک یا اعتبارنامه‌های آن‌ها تغییر نکردند.

این اجرا، مهاجرت یکپارچهٔ20مرحله‌ای، نقش‌های واقعی runtime در Compose،
کل آزمون‌های پروژه، build، دستگاه یا سرور زنده را تأیید نمی‌کند؛ این موارد
در این بررسی متمرکز **UNVERIFIED** هستند و هماهنگ‌کننده جداگانه اجرا
می‌کند. مشاهدهٔ تمام فیلم‌ها، اجازهٔ واقعی ارائه‌دهنده، بازبینی متخصص،
هم‌ترازی کامل کتاب جاری و انتشار محتوای واقعی نیز **UNVERIFIED** هستند.

قبل از انتشار واقعی باید مالک برای محیط و اقدام زنده مجوز بدهد، بازبینی
متخصص و مستند حقوق استفاده کامل شود و مسیر اپراتور واقعی با آزمون مستقل
و rollback طراحی شود. محدودیت synthetic-only این نسخه را برای آن کار
دور نزنید.
