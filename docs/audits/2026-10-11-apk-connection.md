# بررسی صفحه نشانی اتصال APK — ۲۰۲۶-۱۰-۱۱

## علت نمایش صفحه

در کد نسخه آزمایشی اندروید، `RuntimeConfigStore.load()` در نصب تازه و نبود تنظیم ذخیره‌شده، `RuntimeConfig()` خالی برمی‌گرداند. `main.dart` وقتی تنظیم اتصال وجود ندارد، `EndpointSettingsPage` را پیش از صفحه ورود نشان می‌دهد. این کادر **نشانی HTTPS سرویس API خانواده** را می‌خواهد؛ رمز عبور، توکن، کلید یا شناسه کاربر نیست.

نداشتن آدرس پیش‌فرض عمدی است: هنوز یک سرویس عمومی سازگار و تأییدشده برای این APK تحویل نشده است. واردکردن یک دامنه یا ذخیره تنظیم، به‌تنهایی اتصال آنلاین را برقرار یا صحت سرور را تأیید نمی‌کند. این بررسی از کد انجام شد؛ مشاهده صفحه روی دستگاه مالک گزارش مالک است و بازاجرای مستقل نصب روی دستگاه **UNVERIFIED** است.

اندروید نشانی را در `SharedPreferencesAsync` با کلید `lifeguide.api_endpoints.v1` ذخیره و در اجرای بعدی بازیابی می‌کند. سرویس قابل تغییر است و نشانی‌های جایگزین با انتخاب صریح کاربر حفظ می‌شوند. هیچ تغییر در دامنه، سرور زنده، احراز هویت، API پیش‌فرض یا داده نمایشی ایجاد نشد.

## بررسی دامنه توسط هماهنگ‌کننده پروژه

هماهنگ‌کننده در ۲۰۲۶-۱۰-۱۱ درخواست‌های فقط‌خواندنی را اجرا و نتایج زیر را گزارش کرد:

| مسیر `https://app.lifeguide.ir` | نتیجه مشاهده‌شده |
| --- | --- |
| `/` | HTTP 200، عنوان HTML برابر `LifeMate` |
| `/config.json` | HTTP 200 با `text/html` و عنوان `LifeMate`؛ تنظیم JSON نیست |
| `/api/health` | HTTP 200 با `text/html` و عنوان `LifeMate`؛ پاسخ سلامت JSON نیست |
| `/api/ready` | HTTP 200 با `text/html` و عنوان `LifeMate`؛ پاسخ آمادگی JSON نیست |
| `/health` | HTTP 200 با `application/octet-stream`؛ این نتیجه به‌تنهایی سازگاری API را ثابت نمی‌کند |

این نتایج دلیل کافی برای معرفی دامنه به‌عنوان نشانی اتصال این APK نیستند. وجود یا نبود همه مسیرهای احتمالی API، دسترسی بدون VPN در ایران و ورود واقعی دستگاه به آن دامنه **UNVERIFIED** است. هیچ تغییر DNS یا استقرار عمومی انجام نشد.

## اصلاح تجربه کاربر

- نصب تازه عنوان «راه‌اندازی نسخه آزمایشی» و توضیح روشن نیاز به سرویس فعال و سازگار دارد. اگر نشانی تأییدشده تحویل نشده، کاربر مجبور به حدس‌زدن URL نیست.
- فیلد با عنوان «نشانی اتصال API» مشخص شده و صریحاً از واردکردن رمز، کلید یا توکن منع می‌کند. نشانی باید دقیقاً همان HTTPS و مسیر اعلام‌شده توسط مدیر سرویس باشد؛ `/api` را خودسرانه به آدرس اضافه نکنید.
- دکمه ذخیره برای مقدار خالی غیرفعال است. متن توضیح می‌دهد که ذخیره تنظیم آزمون اتصال نیست و نیاز به ورود واقعی بعدی دارد.
- حالت ویرایش، خروج از حساب و پیامد تغییر سرویس برای داده‌های ارسال‌نشده را توضیح می‌دهد. منطق موجود تأیید تغییر حساب/سرویس و پاک‌سازی دامنه داده تغییر نکرده است. پیش از تغییر، داده‌های ارسال‌نشده باید به سرویس قبلی تأیید برسند؛ حذف برنامه یا پاک‌کردن داده‌ها توصیه نمی‌شود.
- نشانی‌های جایگزین اختیاری، انتخاب دستی و اعتبارسنجی HTTPS بدون اعتبارنامه/پارامتر/fragment حفظ شدند. نشانی عمومی پیش‌فرض یا اتصال خودکار به دامنه قدیمی اضافه نشده است.

## شواهد اجرای آزمون

اجرا با Flutter 3.47.6 در پوشه `apps/lifemate`:

```sh
flutter test test/endpoint_settings_test.dart test/runtime_config_test.dart --reporter expanded
flutter analyze lib/endpoint_settings.dart test/endpoint_settings_test.dart
```

چرخه RED ابتدا دو شکست مورد انتظار در توضیح نصب تازه و هشدار ویرایش داشت. اجرای GREEN نهایی: **۱۹ آزمون موفق، صفر شکست**؛ پنج آزمون صفحه اتصال و چهارده آزمون موجود تنظیم/نشست. آزمون‌ها از ویجت واقعی و callback ذخیره مصنوعی استفاده می‌کنند؛ هیچ سرویس عمومی یا دستگاه واقعی را متصل نکرده‌اند. تحلیل ایستا: `No issues found!`.

لاگ‌های محلی اجرای واقعی:

- `/workspace/scratch/endpoint-onboarding-red.log`
- `/workspace/scratch/endpoint-onboarding-green.log`

پس از این آزمون‌های هدفمند، بسته ادغام واقعاً۱۱۲ آزمون Flutter و ساخت APK0.6.0/code5 را در [CI اولیه](https://github.com/davoodmehraban89/LifeMate/actions/runs/38113435509) اجرا کرد؛ job Flutter موفق ولی کل CI به علت هشت آزمون backend لغوشده ناموفق بود. [رسید تفکیک‌شده](evidence/ci-learning-initial-2026-10-11.json) و [گزارش ادغام](2026-10-11-learning-verification.md) نتیجه اصلاح بعدی را ثبت می‌کنند. نصب Android، حفظ تنظیم پس از restart واقعی دستگاه، اتصال عمومی و پذیرش iPhone/Safari همچنان **UNVERIFIED** هستند؛ ساخت فایل جای پذیرش دستگاه نیست.

## اقدام مالک

در حال حاضر مالک نیازی به رایانه، واردکردن URL حدسی، تغییر DNS یا ارائه رمز/توکن در گفتگو ندارد. پس از آماده‌شدن سرویس مورد تأیید، مدیر سرویس نشانی کامل HTTPS را تحویل می‌دهد؛ آن نشانی یک‌بار در این صفحه ذخیره می‌شود و سپس ورود با حساب آزمایشی و آزمون همگام‌سازی انجام می‌گیرد. تا آن زمان، APK آزمایشی به‌تنهایی سامانه آنلاین عمومی قابل استفاده نیست.
